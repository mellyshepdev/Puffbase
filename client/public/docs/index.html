Overview

Puffbase combines the pieces you normally stitch together from four different vendors: source hosting, CI, edge deployment, and AI-assisted site generation. Every surface is reachable from one account:

  • Forge — an embedded Gitea at git.puff-base.com hosts your repositories over HTTPS and SSH.
  • Dashboard — dash.puff-base.com is the day-to-day UI: repositories, issues, merge requests, pipelines, deployments, and the document editor.
  • Console — admin.puff-base.com is the operator surface for services, metrics, and account administration.
  • Builder — describe a site, get a generated preview, revise it in chat, and publish it straight to the edge.

Accounts & single sign-on

One identity covers everything. Sign-in runs through Keycloak (auth.theofficialblacksheepco.com, realm puffbase), and the session cookie is scoped to .puff-base.com — so logging in on the console carries you into the dashboard and back without re-authenticating.

  • Console logins start on admin.puff-base.com; the OIDC callback lands on puff-base.com and the session follows you.
  • New accounts are provisioned from the dashboard's sign-up dialog.
  • Admin surfaces are gated by an allowlist — non-admin API routes return 403.

Git credentials are never stored. Every git operation exchanges for a per-user pufftoken minted in OpenBao at call time — there is no static daemon token to leak.

The forge

Repositories live on the embedded Gitea at git.puff-base.com.

  • Clone / push over HTTPS — https://git.puff-base.com/<owner>/<repo>.git
  • SSH — port 2222, keys managed in your Gitea profile
  • Browse and edit in the dashboard — the repository pages proxy the forge: file trees, file read/write/delete, and commits all flow through the API without leaving the UI
  • Registration is closed — accounts come from Puffbase SSO, keeping the forge private to the community
git clone https://git.puff-base.com/you/project.git
# or
git clone ssh://git@git.puff-base.com:2222/you/project.git

Documents

A document is a private, versioned space — like a repo that only exists to be written in. Every save lands as a commit, so the full history of a spec, runbook, or set of release notes is always recoverable.

  • Create one from New → Document in the top bar.
  • Browse the tree, read files, write changes, and delete paths — all through the editor UI or the /api/documents endpoints.
  • Document names are lowercase-with-dashes; the name becomes its address in the editor.

Pipelines

Pipelines are powered by Gitea Actions — the same workflow syntax as GitHub Actions. Push a .gitea/workflows/*.yml file and runs appear on the dashboard's Pipelines page automatically.

  • Trigger on push, pull request, or a manual dispatch.
  • Runs and their status show up alongside the repository they belong to.

Deployments

Deployments are wired straight into the edge. When you register a deployment, the Locator service learns about it and emits a Traefik router on the next poll — your site answers at its own address on the deploy domain with TLS handled at the edge. No ingress config, no certificates to request.

  • Create — New → Deployment, name it, point it at the service.
  • Inspect — the Deployments page lists every site with its live address.
  • Update / remove — patch or delete a deployment and the edge router follows.

Published sites share a single static host, and the platform emits routing — you never touch a web server config to go live.

AI site builder

The builder turns a description into a published site. A CrewAI crew plans and drafts the page, a local LLM renders it, and you iterate in chat until it looks right.

The flow

  • Describe — create a builder project with a prompt describing the site you want.
  • Preview — the generated page renders at a private preview URL.
  • Revise — ask for changes in plain language; each revision regenerates the preview.
  • Publish — one click pushes the site through the deployment pipeline to a live edge address.

Builder projects are card-gated: attach a payment method (/api/builder/projects/:id/card-setup) and confirm before generating. Publishing runs on your plan's allowance.

Plans & billing

Plans set your limits — repositories, deployments, builder projects, and collaborators. Billing runs through Stripe for subscriptions and Lago for usage metering, so metered features bill on real consumption rather than flat guesses.

  • Free — personal and business accounts, community repositories, the document editor.
  • Paid tiers — raise deployment and builder limits and unlock paid integrations.
  • Manage or change your plan from the dashboard's Plan page.

Integrations

Integrations pull external tools into the same workflow:

  • Linear — Linear issues surface inside the dashboard (/api/linear/issues) so triage lives next to your code.
  • Notion — sync docs and release notes into a Notion workspace.
  • Mail & notifications — deployment and account events notify by mail.

Connect and configure them from the dashboard's Integrations page.
